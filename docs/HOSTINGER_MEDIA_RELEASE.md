# Hostinger release checklist for the media update

Do not perform these deployment steps until the owner approves the reviewed local result.

1. Take a full Hostinger database and uploads backup and verify a rollback path. Preserve the existing artist/song IDs and metadata; do not overwrite a live database with the cloud demo database.
2. Prepare private staging on supported, patched WordPress and PHP 8.3 with HTTPS, correct site URLs, and an indexing restriction. Confirm the actual host's PHP upload/post limits exceed the approximately 20 MB photo-containing plugin ZIP; 64 MB is a practical target. SFTP is an alternative.
3. Build `npm run package` in the reviewed checkout. Deploy the theme and companion plugin ZIPs to staging, including `plugin/data/` and all six original JPEGs plus `media-assets/ATTRIBUTION.md`. Never deploy `.env`, `.runtime`, SQL backups, tests, node_modules, or the full cloud web root.
4. Open Artists → Import supplied research only if content requires synchronization. Review protected records rather than forcing overwrite. Keep all existing URLs, manual edits, null values, and review/noindex flags. No popularity ranking is established by this handoff.
5. Open Artists → Media and embeds. Review the matched/missing/preserved counts. Catalog records must exist before applying. Sync checked mappings and credits; verify 100 managed track mappings, exactly six reused/created licensed photo attachments, four placeholders, and one credits page. Repeating sync must not add attachments or posts.
6. Verify card and profile attributions: photographer, source, license link, changes, and access to full Media Credits. Confirm SHY Martin's actual scaled image files are distributed with the CC BY-SA 4.0 credit/permission record. Maintain the photo-specific licensing exception to the code's GPL license. Do not crop signatures or use these photos as artist endorsements or paid artist advertisements.
7. Verify original abstract song/listing art remains outside Spotify widgets. Players must load only after an explicit choice, have no autoplay query, remain unmodified/unobscured, and retain direct Spotify fallback links. Test allowed, blocked, and slow player behavior on the actual host and mobile connection.
8. Finish the actual operator's privacy/contact/copyright notices, correct public contact email, and consent/cookie behavior for Spotify and any future services. The updated starter notice is a template, not a reviewed legal policy. Current Spotify widget terms and applicable personality/publicity rights must be considered for the actual release; future ads must not obscure widgets or receive Spotify-derived data.
9. Check directory search/genre/mood/country filters, profiles, all selected song pages, artist/song recommendations, source links, image decoding, source/license links, keyboard navigation, mobile layouts, sitemap/noindex behavior, and 404 responses. Purge supported caches and verify public URLs after changes.
10. Obtain the owner's final public-launch approval, then activate the approved production changes and deliberately change indexing settings only for fully reviewed content. No ads, analytics, DNS changes, purchases, or production publication are part of this local implementation task.

Four unresolved photographs remain placeholders until a specific alternative's rights are independently established and the owner approves changing that artist's published placeholder status. A press-kit download link, stock preview, or public social/Spotify photo is not an automatic reuse license.
